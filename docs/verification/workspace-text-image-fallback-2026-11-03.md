# 专业工作台文案图片兼容修复

用户于 2026-11-03 确认：生成文案时，模型支持图片则正常传图；不支持则仅传文字，不因图片能力不足报错。

## 实现

- 移除文案任务受理阶段对“不支持图片模型 + 图片”的直接拒绝。
- `build_copy_request` 按任务绑定模型的 `supports_images` 选择图片：不支持时发送空 `images`，不调用素材加载器；支持时保留图片字节、格式校验与四张上限。
- 保留原始任务输入、商品参考图、报价与幂等请求哈希。现有素材归属、完整性及其他参数校验继续执行，不修改图片／视频生成流程。
- 模型配置与图片能力仍在任务受理时固定，重放请求不重新选择模型。

## 验证

- 文案适配器、默认模型、快速生成单元测试：140 passed。
- 修改的四个 Python 文件 Ruff 检查通过。
- 更新 HTTP 集成用例，覆盖两种图片能力下的受理、原始输入／报价保留以及模型能力变化后的幂等重放。
- 本次数据库集成验证尚未完成：隔离测试 MySQL 在 localhost 与 WSL 地址的 13306 端口均拒绝连接；不计为通过。初次沙箱执行还遇到临时目录与套接字限制，改用项目内测试目录并在允许访问本机服务的环境下重试后得到上述结果。
