## 已实施

- 删除后台「文本服务接入」列表、Agent 编辑抽屉、发布按钮及其前端状态/请求代码；不使用隐藏样式。手动发布真实文本协议或内部文本身份的后端入口拒绝写入。
- 模型列表增加显式默认选择、默认标记、修改原因与冲突处理；新增管理员 GET/PATCH `/api/v1/admin/text-default-model`，保留授权、CSRF、连接版本与选择版本校验、脱敏审计。
- 迁移 `0025_text_default_model` 仅在既有连接单例增加远端模型 UUID 和独立默认选择版本。服务 origin 更换时清除默认；不复制模型参数或模型 Key。
- 新文本任务使用 web 数据库的加密服务连接与指定默认模型。受理前查询远端实际能力及启用状态；无图片能力时含图片的请求在冻结积分前拒绝。API 与 Worker 不需要新增环境 profile。
- 平台内部「文本创作」采用服务端固定协议身份 `text-agent-v1`，由默认设置自动维护。技术输入契约由代码验证，不再要求管理员重复填写 Agent 端点、profile 引用或输入政策。商业规格、价格、生成开放、容量及结果政策继续走原有检查。
- 接入目录能力固定为文本服务协议的上限，模型图片能力按请求校验；更换默认模型或编辑图片能力不会改变内部 Agent 版本、停用原规格，也不会影响已提交任务。
- 受理快照只固定原服务 origin、模型 UUID 与能力；Worker 读取当前数据库凭据访问原路由。默认切换不重定向旧任务；服务 origin 不符时拒绝使用新服务。保留旧环境 profile 仅用于历史旧快照兼容。

## 复核与修复

独立只读代码复核发现三个 Important 问题：模型图片能力改变导致规格版本失效、空输入政策导致内部 Agent 无法配置、编辑当前默认模型后目录能力不同步。已通过失败测试复现并统一修复：固定技术契约/版本，按实际提交校验模型能力，并单独显示生成开放尚未配置的状态。重新验证后，下述检查均通过。

采用当前开发工作区，因为本任务依赖大量未提交的既有文件；保留其他改动，无提交、重置、合并或发布。该决定的限制是本次改动没有独立 Git 提交边界，以本记录列举文件与行为为核查范围。
