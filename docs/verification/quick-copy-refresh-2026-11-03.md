# 快速生成营销文案刷新修复

日期：2026-11-03。用户先要求排查、确认结论，再明确授权修复文案重复刷新和任务完成后继续轮询。本次仅本地实现，未部署，未创建真实收费任务。

## 原因与修复

原先每 3 秒读取进度时，只要用户没有手工修改，就用服务端草稿覆盖页面。新生成的文案保存在作品中，服务端草稿仍为空，因此页面先清空，再重复读取作品回填；整个草稿的报价监听还会重新请求报价。

- `useQuickGeneration.ts` 比较前后服务端草稿与当前文案批次。它们未变化时只更新任务进度，保留已回填文案；新批次、服务端草稿变化及明确重新读取仍应用新草稿。已有未保存编辑和版本冲突保护保留。
- 报价监听排除文案生成结果，保留图片报价需要的详情文案及其他创作参数依赖。
- 自动进度读取覆盖整个流程，而非当前查看阶段。成功且 `CONSUMED`、失败等待人工重试/释放、关闭且不再冻结时停止。空草稿不轮询；队列、生成、保存、恢复、核查及尚未结束的成功/关闭结算继续读取。
- 提交中、提交结果不明、进度/文案读取失败保留恢复；新批次提交后自动恢复。TaskCard 既有重试通知触发即时读取，后续运行任务继续轮询，首次读取失败也会恢复。
- 余额读取失败可单独重试，不需要重启已完成任务的进度轮询。

未改动后端生成、扣费、任务提交协议和页面布局。保留工作区原有未提交修改（包括已有的文案回填基线与导航保存修复）。
