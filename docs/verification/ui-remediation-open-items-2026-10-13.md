# 界面整改：尚未对齐原型的项目

日期：2026-10-13。状态：待用户提供改造计划／明确接口与政策安排。本清单中的项目不计为已完成、原型一致或生产验收通过。

这些主要是原型与现有真实接口之间的欠交付和约束差异，不是代理已判定“原型不合理”。本轮没有擅自补假数据、修改业务政策或删掉原型要求。详细证据见[用户页面核对](ui-remediation-user-pages-2026-10-13.md)、[后台核对](ui-remediation-admin-2026-10-13.md)及本轮 W 任务报告。

## 优先处理的缺口

| 编号 | 原型要求 | 目前实际缺口 | 为什么本轮未补 | 需要后续计划明确的内容 |
| --- | --- | --- | --- | --- |
| P-01 | 个人资料有店铺名称、主营类目、联系邮箱、联系电话；账号详情有状态和注册／最近登录时间 | 普通用户资料接口没有这些字段 | 本轮不改真实契约，也不将这些内容假写入简介 | 为哪些字段增加存储、读取、保存和校验；账号状态与时间取值来源 |
| P-02 | 失败任务可修改后重新提交 | 现有恢复入口依赖作品来源；失败任务没有作品，任务详情缺素材可用性 | 不假设失效素材仍可用，不自创恢复流程 | 失败任务输入恢复接口、素材失效处理、重新报价及原任务关联方式 |
| P-03 | 任务详情显示任务记录／事件时间线 | 普通任务详情未提供事件列表 | 不用前端推算或虚构历史事件 | 事件接口、时间与状态文案，以及恢复中事件的显示规则 |
| P-04 | 后台可搜索和维护用户，显示店铺／最近登录／任务数／列表积分 | 当前管理列表字段与查询能力不足，新增／编辑／重置密码／删除没有对应完整接口 | 不造无法提交的入口，不将单页筛选冒充全局搜索 | 后台用户维护、全局查询与账户生命周期政策 |
| P-05 | 原型是简洁的 Agent 配置及规格／价格联合表单 | 真实契约有参数类型、范围、组合、政策与版本；规格／价格各自独立发布 | 不丢失正式约束或伪造原子保存；高级 JSON 已折叠但未消除 | 原型简表如何表达正式约束；规格／价格的发布与冲突处理计划 |
| P-06 | 任务关键词／Agent 筛选、平台流水、按 Agent 用量与状态统计、日志原因搜索 | 对应真实查询和聚合接口未齐 | 不把已加载页或管理员审计当成平台总账与全局统计 | 筛选、聚合接口及统计口径；授权可见范围 |

## 其他已登记差异

| 项目 | 实际情况与边界 |
| --- | --- |
| 原型与真实字段长度／密码要求 | 原型演示与真实契约的昵称、简介、密码限制不同，保留实际校验，待统一；没有降低安全限制 |
| 作品名称与来源会话标题 | 作品 DTO 缺显示名称或会话标题，当前按类型展示并提供真实来源入口 |
| 作品重新生成的起点 | 当前需恢复资料草稿并在工作台重新报价；原型直接进入再次收费确认，尚未完全一致 |
| 素材原文件名 | 素材引用仅含版本／标识，界面使用“商品参考图”序号，不伪造原名称 |
| 动态参数显示信息 | 已知原型字段已中文化；接口未提供完整 label/help 与提交时中文元数据，未知项不能声明精确还原 |
| 注册按钮与演示提示 | 真实“创建账号／登录”不带“演示”，不将原型赠送演示数值写成政策 |
| 删除、停用与授权 | 真实操作依赖已确认政策，未决时仍禁用，不因原型演示可点而自动开启 |
| 后台用户详情的积分快捷操作 | 原有安全快捷入口继续保留，同时恢复独立积分模块；尚非逐按钮完全一致 |
| 后台统计成功率 | 服务端使用成功÷终态，原型示例使用成功÷全部；保留真实分母，未擅自改口径 |
| 未知审计类型／字段 | 常见项已中文化，未知标识保留以免丢失审计证据；完整展示名称需要配置计划 |
| 官网维护与案例批准 | 保留实际批准版本、冲突控制和独立展示许可；原型演示保存不能代替生产发布 |
