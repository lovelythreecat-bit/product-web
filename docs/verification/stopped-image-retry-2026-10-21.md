# 图片停止任务重试 · 2026-10-21

用户要求快速生成图片失败后增加重试，并确认将 `UPSTREAM_NEEDS_INPUT` 已停止图片任务纳入范围。

## 原因与修改

实际“精品男装”主图、长图为 `INVESTIGATING / FROZEN`，上游为 `completed / needs_input`，旧按钮只适用于 `FAILED / FROZEN`，且旧状态文案显示“正在核验完整成果”。

- 任务卡现在显示“等待补充资料”、停止原因说明及“重试”；沿用原有确认弹窗、原资料、冻结积分和幂等重试请求。已完成历史仍只读。
- 服务端先验证所有者及持久化上游身份，获取任务租约，再重新查询原任务及结果。仅在已停止、无产物、明确 `image_calls == 0` 时，写入身份绑定的持久观察，经既有失败证据归约与状态转换后开放原重试流程。
- 自动查询仍保持 `NEEDS_INPUT` 等待；未知、运行中、已有图片调用或部分产物不重发。原冻结积分仅在既有受理事务中转交唯一重试后继；快速生成继续跟踪该后继。

## 验证

- 后端相关单测 138 项通过（图片适配、失败重试、停止任务权限/身份门槛、等待恢复、媒体执行）。
- 隔离 MySQL + Redis + 本机 HTTP 集成测试 2 项通过：零图片调用允许进入失败重试状态，已有图片调用拒绝；均不额外调用生成、不消费或释放冻结积分，租约正常退出。
- 前端任务卡、快速生成及媒体工作台单测 82 项通过；`vue-tsc --noEmit` 通过。
- ego 浏览器检查实际任务的主图/长图重试按钮、原资料和 20 积分确认弹窗、取消操作；手机 390px 宽度按钮检查。
- 未对用户真实任务点击“确认重试”，未调用真实收费生成模型。
