# 工作台任务恢复与并行生成

日期：2026-10-16。用户反馈退出重进后进行中任务消失、上一轮未完成阻塞新任务，并明确选择「允许多个任务同时生成」。

## 根因与改动

- 顶部工作台入口不带会话编号，原实现展示空任务区。现在以账户最新持久化任务定位原会话，刷新与返回均读取原任务，不提交生成请求；无历史任务仍进入空工作台，显式新建会话不触发恢复跳转。
- 本机 D-05 旧政策明确限制每人 1 个未完成任务。并发政策新增显式 `null` 表示不按账户未完成任务数量拒绝新任务；字段仍必填，其他明确正整数上限仍执行。积分、存储预留、权限与幂等校验继续执行。
- 原 Worker 同步逐条处理；新增 `--concurrency`，默认 4 个独立消费者，每次领取 1 条消息，沿用数据库租约防止重复执行。超过执行槽位的新任务可正常受理，等待可用槽位。
- 前端将结构化 429 / RATE_LIMITED 视为明确拒绝，解除原请求锁；提交中状态按会话草稿隔离，旧会话的慢请求不锁住新会话。代理错误、回执缺失等真正不确定的请求仍保留原幂等标识与正文。

## 验证

- 前端相关 5 文件、30 项单元测试通过，包含提交中切换会话、429 解锁、原请求恢复、持久化任务读取与历史资料回填。
- 桌面 1440×1000、手机 390×844 浏览器回归各 1 项通过：空入口恢复原进行中任务、整页刷新、离开工作台返回、旧任务生成中提交新任务、回看原任务。全部为确定性 HTTP 测试数据，未调用真实模型。
- 后端相关 39 项单元测试通过，涵盖并发政策、并行执行槽位、故障隔离及配置读取。
- 隔离 MySQL / Redis 共 5 项集成与故障测试通过：有上限仍拒绝超额请求、显式无上限接受两个并发任务、重复请求不重复冻结、多 Worker 租约隔离及原单步 Worker 行为。
- 前端 TypeScript、生产构建通过；本次后端变更 Ruff 检查通过。

## 本机配置

追加不可变政策版本 `TEST_ONLY_parallel_generation_20261016`，只替换环境中的生成 D-05 引用，保留旧版本供历史任务使用；原任务、输入快照、已冻结积分与账本不做数据修正。实施脚本在忽略目录 `.local-data/enable-parallel-generation-20261016.py`，写入本机配置审计。

本机启动方式：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:application --factory --host 127.0.0.1 --port 18000
.\.venv\Scripts\python.exe -m worker.main --stream TEST_ONLY:local-text:20261016 --group local-generation-workers --concurrency 4
```

本机配置已应用，并已重启经进程路径与父进程核对的项目 API / Worker。`/api/v1/health/ready` 返回 200 / ready=true；Worker 启动日志确认 `concurrency=4`。只读复核新 D-05 的 `max_concurrent_tasks=null`；原进行中任务仍为 RUNNING / FROZEN，未被取消或人工结算。本次未额外提交真实收费生成。日志保存在忽略目录 `.local-data/api-workspace-recovery.*.log` 与 `.local-data/worker-workspace-recovery.*.log`。

## 追加：费用核对状态跨会话锁定

用户反馈新会话显示积分数值但创作按钮全部灰色。补充回归复现了一条对应路径：旧会话发起费用核对并等待报价时切换到另一会话，新会话即使取得报价，仍会被共用的 `preparing` 状态禁用整块创作区。费用核对状态现与提交状态一样按会话草稿隔离；原会话仍防止重复核对，旧请求结束或报错不打开新会话的确认弹窗、不写入其错误提示。

新增测试先在旧代码上因新会话表单仍为 disabled 失败，修复后通过。相关 5 文件共 42 项单元测试、TypeScript 与生产构建通过；桌面和手机各 1 项浏览器回归通过，覆盖旧任务进行中创建新会话并确认提交。浏览器使用确定性模拟接口，未提交真实收费任务；本轮未连接到用户正在使用的浏览器标签，未直接核验该标签当前内存状态。
