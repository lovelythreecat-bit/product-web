# 图片、视频并发与本地队列整改

日期：2026-10-20。用户要求两个专项分别多 Agent 排查、在存在同类问题时按文案整改流程修复。实施记录保存在 `.agent-runs/media-queue-20261020/`，由图片专项、视频专项和独立评审三个子 Agent 分工，主任务负责共享调度与运行配置。

## 实际协议差异

| 项目 | 图片 | 视频 |
| --- | --- | --- |
| 上游接纳模式 | 异步持久队列；原工作并发 1、队列容量 100 | 异步持久工作队列；单 Worker 串行执行 |
| 明确队满拒绝 | HTTP 429，扁平 `code=queue_full`，在创建任务前拒绝 | 没有队列容量/并发 429 接纳协议；供应商限流可能发生在已接纳任务内 |
| 同类缺口 | Web 丢失明确拒绝语义并卡入受理不明 | 没有文案“仅成功两项”的接纳上限；Web 缺少执行额度协调，未知确认会重复 POST |
| 本轮额度 | 图片上游工作并发 6，队列容量仍为 100；Web 图片额度 6 | Web 额度按现有真实 Worker 能力设 1；没有虚构上游六路执行配置 |

设置六个图片任务槽位不等于供应商支持六路模型请求；现有模型自身并发和预算政策保留，未执行真实供应商吞吐压测。

## Web 调度与恢复

- 数据库共享配额按协议与规范化服务源地址分开；不同模型、配置、Key 和多个 Worker 不各分一套额度。图片、视频、文案互不占用对方配额。
- 图片、视频为异步接口，接受响应后继续持有槽位，直到任务终态；不会在 POST 返回时立即腾出容量。存量已受理及受理不明任务按原冻结路由接管，避免上线后漏算。释放操作核对任务租约和 fencing token，旧 Worker 不能释放新 Worker 的槽位。
- 图片超额留在本地 `QUEUED`，未获槽位时不上传、不创建上游尝试。只有精确的队满且未受理响应可等待重试；沿用原任务、素材上传引用、完整请求及幂等键，不重复冻结。每个 POST 消耗独立拒绝标记，超时或断连不能复用先前 429 证据。拒绝标记或回执提交后进程中断，也能恢复原队列。
- 视频等待用户输入或方案确认时释放策划槽位。确认、补充资料重新策划都使用用户已经提交的持久命令，先保存命令、队列标记与 outbox，再申请实际额度。Worker 空闲后执行同一命令，不从轮询推导新的确认。进行中的确认、输入命令及未知回执保持槽位，避免旧状态误释放。
- 视频确认 POST 和补充资料 PATCH 的未知结果，只通过 GET 核对原任务；不再次发送未知命令。已保存 generation 或已应用输入直接恢复。命令结果持久化后、队列清理前中断的路径会清理队列并继续轮询与保存结算，避免任务永远停在队列恢复分支。
- 队列进出沿用现有媒体状态和持久事件，保留人工方案确认、任务快照、收费标准与积分语义，没有新增用户字段或擅自推进业务步骤。

## 验证与限制

- 图片专项：81 项单元测试、8 项真实受控 HTTP 用例通过。
- 视频专项：原 39 项单元测试、2 项受控 HTTP / MySQL 恢复用例通过；主任务另补 2 项未知输入只查询的 RED/GREEN 回归。
- 最终统一集成与故障回归：**136 项通过，131.74 秒**，覆盖图片、视频、共享队列、原文案链路及既有上游/调度恢复。
- 最终完整后端单元测试：**777 项通过，2 项既有失败**，60.54 秒。失败仍为 `tests/unit/test_display_numbers.py` 的 `test_task_projection_preserves_number_across_state_changes_and_replay` 和 `test_task_detail_contains_persisted_owned_conversation_number`，测试夹具缺少任务时间字段；与本次排队修改无关，未扩大范围修正。
- 独立评审发现并复核了确认后崩溃、旧租约释放、存量在途接管、输入命令绕过额度、瞬时绑定故障恢复，以及命令提交到队列标记之间的窗口；最终无剩余 P1/P2。评审独立运行 136 项聚焦单测、Ruff 与实际命令辅助器崩溃恢复探针，通过。
- 相关文件 Ruff 通过。测试只使用专用 MySQL / Redis 和受控 HTTP，不调用真实图片或视频供应商。本轮不额外创建收费生成任务。

## 本机生效核验

图片 API、Web API、Web Worker 已安全重载，图片、文案、视频 API 与两个 Worker 的健康检查全部通过。实际配置为图片上游工作并发 6 / 队列 100，Web 文案配额 6、图片配额 6、视频配额 1；Web Worker 启动日志确认六个执行槽位。视频上游 Worker 维持原有单例，没有虚构六路渲染能力。

原有三个手工核查阻塞任务的状态及原因未变：两个文案 `CALLBACK_EVENT_CONFLICT`、一个图片 `UPSTREAM_NEEDS_INPUT`。没有因为本次升级自动重提这些任务或新增收费生成测试。
