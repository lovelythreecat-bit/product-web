## 各步安排

人数为每一步投入的子 agent 数，不含主控；实现与评审分时或在无写入冲突的范围并行。当前总活跃上限4，最大子agent并发3。每一步验证并独立评审后再推进依赖它的任务。

| 步骤 | 子 agent 安排 | 退出条件 |
| --- | --- | --- |
| 计划评估 | 2位独立只读评审；主控修订 | 阻断项修复、DAG与正文一致 |
| T01工程基础 | 1位实现，随后1位独立评审 | 后端启动/门槛测试、前端类型和构建、OpenAPI、隔离MySQL/Redis启动 |
| T02/T03政策与模拟契约 | 每任务1位实现＋1位评审；范围独立时最多2位实现 | draft政策、生产关门、三Agent确定性故障模拟 |
| T04～T07账户/报价/存储/受理 | 每任务1位实现；资金/权限另1～2位评审 | 真实MySQL原子赠送、冻结、报价、容量、幂等与快照证据 |
| T08～T14恢复/发布/SSE | 关键事务按依赖串行；1实现＋1～2评审 | Redis丢失、Worker重启、原成果恢复、互斥结算、断流补偿 |
| T15～T17辅助/作品/生命周期 | 每任务1实现＋1评审，独立辅助可与其他只读验证并行 | 辅助与任务隔离、本人资源保护、按版本生命周期 |
| T18用户前端 | 分共享基础、认证账户、创作作品、跨页验收；每小步1实现＋1评审 | V2界面、真实API主流程、资料持久、素材生命周期与账本一致 |
| T19/T20后台与官网 | 每任务1实现＋1评审；必要时加独立安全评审 | 配置/流水/规格/授权/审计完整、公开案例门槛有效 |
| T21全端回归 | 1修复＋1独立浏览器验收 | 桌面/手机、焦点、溢出、长名称、弹层竞态与F01～08 |
| T22～T24运行与联调 | 1运维或适配实现＋1独立验证 | 真实Agent及辅助证据、备份恢复演练；未决条件记录阻塞 |
| T25总验收 | 1证据汇总＋1独立复核 | 30项AC逐案核对，模拟/真实结果分开 |

主控独占账本更新及共享文件协调；每个文件只有一个写入者。子agent不递归派发，不凭实现者口述接受任务。未满足适用D门槛的生产能力保持关闭，不把模拟通过记为真实验收。后续任务较大时可在保持原编号下补子步骤及依赖，不强行填满并发槽位。

## 工作区与运行环境

在当前项目创建 `codex/platform-development` 开发分支。用户授权在项目落地且未请求另一工作树，本次不迁移工作目录；保留现有原型和设计资产，产品代码新增在backend/frontend/contracts/infra。

Node实际版本22.14.0；可用Python3.12.14、uv0.12.19。默认pnpm来自失效旧路径，使用Codex依赖包提供的pnpm11.25.0绝对路径，应用依赖另锁定。Docker Desktop启动在Inference监听器处报错，不修改其用户配置或重置数据；已有Ubuntu-24.04内独立Docker服务29.3.0可用，开发容器通过WSL调用。项目使用独立容器/卷与非默认端口，避免复用本机MySQL5.7或Redis5作为规定版本的验证环境。

原始评审与尝试存于项目忽略的 `.agent-runs/2026-10-11-development/`，实施进度与证据使用关联运行账本；该记录可恢复但不等于所有步骤已完成。正式交付记录另存 `docs/verification/`。环境、安装或启动失败不能当作业务RED或验收PASS。
