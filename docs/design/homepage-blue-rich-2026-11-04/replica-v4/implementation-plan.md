## 1. 实现原则

- 保留当前 HTML 的正文、价格、七个标题、语义区块和轮播、菜单、模态窗口的 JS。当前主要问题是构图比例与素材，不是需要重写业务。
- 重写桌面视觉 CSS，不能继续在现有多轮修补样式末尾堆覆盖。以此文件的尺寸表建立新的清楚分区样式；所有旧 `min-height`、内边距、字号和图片定位逐项重新确定。
- 图中文字用可选中 HTML；布局、按钮、标签、进度线、边框由 CSS/SVG 生成。照片、角色、复杂立体插画使用独立位图。禁止将整张设计稿或含整段正文的截图作为网页主体。
- 设计图中图片应取与其同构图的独立素材。不能把一个正方形素材板格子随意截成长方形、靠渐变遮罩或粗糙 CSS 示意代替原图。
- 当前允许静态创作示例，注册/支付继续用已有本地说明弹窗，不改变既有声明和业务边界。

## 3. 尺寸和响应式实现方式

建议设一个桌面设计单位，以1024宽为1倍。页面最大视觉宽度可设1440，在其范围内所有桌面主构图尺寸同比缩放，超过1440则居中。这样1024的截图可直接与设计稿对比，1440仍保持同一构图，不因固定字体与放大网格混搭导致卡片变空。

```css
.page-frame { width: min(100%, 1440px); margin-inline: auto; }
/* 整个桌面区域采用同一单位，不仅缩图片 */
:root { --u: min(0.09765625vw, 1.40625px); }
.section { margin-inline: calc(18 * var(--u)); }
.sec-title { font-size: calc(34 * var(--u)); }
```

也可用rem并设置根字号为同样单位，避免每项calc，但不要使用整页transform缩放（会破坏文档尺寸、锚点和弹层定位）。桌面最小断点建议800px，800以下进入独立手机样式并恢复正常px/rem字号；dialog 不受桌面设计单位影响。

1024下内容侧边距18–22px，而当前1280宽容器在1440屏幕上左右75px，视觉占比明显不同。新页应按约96.5%宽的主模块布局。Hero导航与标题自身使用更大的44–47px内边距，不与下方section强行共用一个container值。

手机未有确认稿，以不遮挡正文、按原顺序堆叠、舒适阅读为要求。不能把桌面压成微缩图。三价值卡/场景/作品/套餐单列；行业可单列，能力2列。手机继续使用16px正文、24–28px板块标题和44px触控按钮。

## 4. 字体与密度：先解决结构，再加质感

- 图中文字大部分呈现粗黑体，保留当前无衬线中文系统字体可作为第一步，但需在 Windows 实际字宽下校准换行。标题weight800–900，普通正文400–500，正文主色接近#06134c，板块标题接近#001bcb。
- 1024基准：板块标题34、Hero主标题36、首屏大卡标题24、价值卡大字44、价值副标题21、定位标题21、创作方式标题20/正文12–13、营销标题25/正文14、行业名称20/正文12–13、能力标题20/正文14、套餐名称21/价格30。
- 当前`.scene-viz{min-height:180px}`和营销235/280px直接撑高横栏，必须撤销。创作方式第一/二/三行全部明确独立高度，并让图填满规定区域。营销三行也不能共用同一min-height。
- 当前行业图片165/180高，应为约122/108高；当前能力图150/165高，应为126；当前plan padding20–24、列表gap8与45高按钮叠出过高卡片，应改成约20/14内边距、紧凑18–19行高、28px按钮。
- 标题与短蓝线之间约13px，蓝线到网格约17px；不能使用一套28px外框padding+26px标题margin+17px伪元素margin继续累加。
- 不用空白填充同步三稿高度。应调整正确的字宽、图片比例与间距；文本若比图多一行，先查原句及字体而非隐藏溢出。

## 6. HTML和JS最小改造

1. 保留所有section id、`data-action`、三tabpanel及tab id、`.tab-progress`。保留5000ms、手动重计时、方向键、后台/离屏/减少动态效果、弹窗暂停。
2. 给现有scene增加语义修饰类（如intro/pro/video），按各自图稿控制高度。给图片增加asset类/真实img，尽量避免依赖nth-child大面积重排。
3. Hero大卡与Hero角色分别分层：背景<商品/笔记本<正文/按钮<导航。角色可以跨左栏边缘，但不能覆盖右卡文案。
4. 暂停按钮保留可访问入口，但用角落小图标或焦点/悬停出现的控制，不挤占图稿唯一说明文字的水平中心。保留可见focus状态，改为蓝白焦点环，不使用现有橙色outline（用户明确不用橙色）。
5. Logo保留用户品牌，不用全身人物图或设计截图代替。若官方Logo纵向布局与图中横排不同，应由素材负责人提供符合视觉的横向品牌组合，不手绘替换标志本体。
6. 现有图像弹窗的素材类和示例图也映射到新素材，避免首页新图、点击还是旧图。

## 7. 实现顺序与视觉闸门

1. 保存V3目录为旧版，建立新复刻版或在指定范围替换；不触碰frontend/backend。
2. 先完成1024px黑白线框尺寸：Hero494、上段余1042、中段1536、下段1536。确认模块边界、列宽、标题位置后填素材。
3. 将素材接入精确占位，删除旧图板hack与多层互相覆盖样式；完成颜色、渐变、边框、厚度与阴影。
4. 用1024宽、设备比例1截图，按0–1536、1536–3072、3072–4608三个切片逐图比较。不能只看1440全页缩略长图。
5. 差异清单至少逐项关闭：Hero角色/标题/大卡比例、首屏背景光带、上段价值照片、窄场景行、营销电脑全景、行业图裁切、能力图体积感、套餐高度、Footer密度。
6. 1024对齐后检查1440同比例是否一致，再做390手机与交互复验。只对受影响交互运行检查，不用整套后端测试。
7. 如素材无法还原或生成仍不同，列出实际剩余偏差。不能把“无报错、无溢出”当视觉复刻通过。

验收以设计稿同尺寸逐段截图为证据。坐标误差可客观测量；人物姿态、商品构图、材质质感仍需人工查看，不能以像素差单一数值代替判断。
