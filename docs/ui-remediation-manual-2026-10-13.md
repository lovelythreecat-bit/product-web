# 电商 AI 创作平台界面整改手册

日期：2026-10-13。用途：后续代理进行界面整改时必须先读的执行依据。

状态：用户收到首页 V3 与文案后，要求“多agent分工执行 开始执行”；本轮页面实施、56 项单测、构建与独立评审修复复核已完成，详见[交付与验证记录](verification/ui-remediation-2026-10-13.md)。[未完成项目](verification/ui-remediation-open-items-2026-10-13.md)继续保留。本手册不代表全量原型一致、真实业务验收或上线许可。

## 1. 本次用户指令

1. 首页是重中之重，优先于其他页面整改。先交首页高保真设计稿，再按确认后的稿件编码。
2. 首页可以独立设计，不必参照原型首页的布局；它应是一张真正的宣传类网站首页，炫酷、高大上、有科技感，同时符合已确认主色调。
3. 首页以外，交互、字段、操作流程等严格按照原型执行。不得以“优化体验”“简化实现”或个人判断为由自行改造。
4. 发现原型不合理之处，明确指出问题、影响及位置，由用户提供改造计划。未得到计划前不擅自修改相关设计。
5. 后续修改必须以本手册为依据，不再另起一套无关方案。

本手册初始阶段只交整改文档与首页高保真稿。随后用户明确要求多 agent 开始执行，现进入页面实施；该执行授权不扩大非首页改造或生产发布范围。上述最新指令覆盖历史文件中对首页沿用原型布局的要求；其他业务与视觉边界继续有效。

## 2. 依据与读取顺序

2. [项目产品设计基准](product-design.md)。
3. [首版需求终稿](电商AI创作平台-首版需求终稿-2026-10-09.md)：产品事实、权限、积分、结果与启用边界。
4. [V2 暖色视觉基准](design/high-fidelity-2026-10-11/visual-reference.md)及[图片工作台设计图](design/high-fidelity-2026-10-11/workspace-image-v2-warm.png)。
5. 非首页的[交互原型](prototype/index.html)、[原型说明](prototype/原型说明.md)，以及对应页面和弹层的实际原型行为。截图不能代替点击核对。
6. [开发计划](superpowers/plans/2026-10-09-ecommerce-ai-platform.md)、本次适用阶段及[当前业务范围](development-scope-2026-10-13.md)。
7. 首页本轮交付的[设计说明](design/homepage-2026-10-13/design-brief.md)与高保真图。只有经用户确认的具体版本可以作为编码基准。

| 内容 | 执行依据 | 不得替代的内容 |
| --- | --- | --- |
| 首页宣传布局与视觉表达 | 本轮独立高保真设计，确认后执行 | 不能沿用现有空壳；不能将工作台三列布局直接套到官网 |
| 非首页字段、按钮、流程、弹层与业务结构 | 原型实际行为及用户后续改造计划 | 不能自行增删字段、替换步骤或变更默认行为 |
| 非首页视觉 | 已确认 V2 暖色稿与规范 | 不能退回历史绿色，也不能只换颜色而忽略构图 |
| 真实权限、计费、数据与能力 | 需求终稿、服务端契约及用户确认 | 原型演示数值不能写成生产默认值 |

发现依据之间有冲突时，记录冲突并交用户处理。不得一边声称严格按原型，一边自行选择另一套交互。

## 3. 已确认的问题与整改目标

| 已核查问题 | 证据 | 整改目标 |
| --- | --- | --- |
| 首页路由存在，但当前页面是标题、按钮与空内容，缺少完整宣传展示 | `frontend/src/features/site/HomeView.vue`；本轮浏览器查看 | 首页单独设计，形成完整宣传页面与有吸引力的首屏 |
| 当前首页能力和流程依赖批准内容，有内容缺失时整个模块消失 | `HomeView.vue` 中条件渲染 | 设计稿必须覆盖完整页面；后续区分设计预览与实际发布状态，不能用无内容的运行页面作为视觉交付 |
| 共享主题色存在，但没有足够证据证明整体还原高保真 | `frontend/src/styles/tokens.css` 与 V2 稿 | 逐项对照比例、层级、留白、组件、图片与操作区域，主题色只是其中一项 |
| 历史限定代码评审通过，但完整视觉尚未验 | `docs/verification/T20a-site-content-2026-10-12.md`、`T21a-ui-finish-2026-10-12.md` | 分开登记代码、交互与视觉结果，不用局部 PASS 代替整页验收 |

这些是本轮文件与页面核查结论，不是对历史 token 使用的完整归因。不得虚构已检查的页面、交互、截图或费用统计。

## 4. 首页：最高优先级

### 4.1 目标

访客第一屏应能理解这是面向电商的 AI 文案、图片、视频创作平台，看到具有吸引力的商品创作表现，并知道下一步如何注册或了解产品。

首页是宣传展示页面，允许重新组织信息、视觉和浏览节奏。首页的创意自由不延伸到登录、注册、创作、作品、账户与后台的业务交互。

2026-10-13 文案追加要求与确认：首页宣传文字要自然、活泼、有吸引力，不写成后台功能说明。用户已确认“让好商品，亮眼登场”等轻快、有画面感的文案方向。首屏突出商品创作与表现价值，“作品保存”等辅助功能放到相关模块。当前具体文案登记于首页设计说明；费用、按钮去向与能力边界仍需准确，不作销量或效果保证。该确认不改变非首页原型文字与交互，也不代替完整首页稿或生产公开发布的确认。

### 4.2 视觉方向

- 2026-10-13 用户已否决咖啡主题首稿：不得将整页设计成咖啡、奶茶、餐饮或单个消费品牌广告。首页应明确体现服务多品类商家的电商创作平台，以鞋服、美妆、数码等不同品类的商品素材与文案／图片／视频成果展示平台能力。不能只更换一个商品、继续套用单品牌广告叙事。
- 延续奶油米色 `#F8F3ED`、陶土橙 `#A94E32`、暖棕文字 `#322823`、浅色面板 `#FFFDFA`。
- 大字号、明确对比、精确对齐与充足留白，呈现成熟宣传网站的层级。
- 科技感通过立体商品视觉、精细光轨、创作成果的空间编排、数据流动感和有节制的动态表达建立。
- 首页可探索局部暖色光晕、金属材质与少量深暖棕对比区；这些属于本轮设计提案，不自动替换非首页 V2 控件规范。
- 商品与创作成果是主角，装饰服务内容。不得用满屏霓虹、无关机器人、随机粒子、密集玻璃卡片或空泛科技词堆出“科技感”。
- 不更换为蓝紫色主视觉，不做后台式导航与表单首页。

### 4.3 设计范围

| 区域 | 设计内容 | 成功标准 |
| --- | --- | --- |
| 顶部导航 | 产品标识、能力与流程等页内入口、登录与注册 | 宣传网站的导航清晰，注册为主要行动 |
| 首屏 | 产品价值、大标题、简短说明、注册入口、商品与成果的核心视觉 | 首屏具有吸引力，能读懂产品用途；不能仅有文字与大块空白 |
| 三种创作能力 | 文案、图片、视频的差异化表现 | 信息真实，视觉上能区分能力，避免重复卡片占满全页 |
| 商品到成果的机制展示 | 商品资料与三类输出的关系 | 呈现已有产品能力，不暗示平台具备自动串联、自动选 Agent 或批量发布 |
| 使用过程 | 准备资料、选择能力与规格、确认费用、查看成果 | 浏览顺畅、文字精简，与需求的实际流程一致 |
| 展示与案例 | 可标注的设计样例；真实案例独立受授权控制 | 设计样例不能包装为真实客户产出或已接入结果 |
| 底部行动与页脚 | 注册行动、必要说明与入口 | 用户看完后有明确去向，页脚完整 |

以上是首版设计组织建议，可在首页稿中调整构图；它不是新增功能清单。

### 4.4 高保真交付要求

1. 先交一版完整桌面高保真稿，既展示重点首屏，也展示后续内容结构，不能只用文字描述设计。
2. 保存设计图、生成提示词和设计说明，标记版本、日期、状态及示例边界。
3. 说明未来手机端的内容顺序与视觉降级方式；桌面稿不能冒充手机稿已完成。
4. 高保真图中的标题、按钮和模块名称在设计说明中登记准确文字；图像模型文字误差不能直接进入代码。
5. 展示具体稿件供用户评阅。用户提出修改时，修改该版本并保留可追踪记录，不重新随机选风格。
6. 用户确认具体稿件后，再写首页组件、准备可独立使用的素材与动效。不得将整张设计图作为背景嵌入充当网页实现。

### 4.5 产品事实边界

- 产品名称尚未最终确认，暂定名称在设计说明中明确，不自创已获确认的品牌。
- 不虚构客户数量、节省比例、生成速度、成交数据、合作品牌、评价、价格、案例授权或真实 Agent 接入状态。
- 三个真实 Agent 仍在调试，当前只预留接口；首页设计不得被记录成真实功能已启用。
- 开发设计预览可展示明确标注的示例；生产公开文案与案例继续遵守批准、归属及授权规则。
- “内容待批准”不等于“设计工作可以缺失”；设计预览与可公开发布内容分别登记。

## 5. 非首页：严格执行原型

### 5.1 必须保持一致的内容

| 类别 | 必须核对的内容 |
| --- | --- |
| 字段 | 名称、顺序、分组、控件类型、必填性、提示、默认值、只读与编辑状态 |
| 按钮 | 文案、位置、显示时机、启用条件、点击结果、保存与取消行为 |
| 导航 | 入口、目的页、返回方式、当前状态、手机端入口 |
| 页面结构 | 摘要、列表、详情、表单、结果的组织与默认显示内容 |
| 弹层 | 抽屉／居中弹窗／原位展开的选择，标题、操作区、关闭、焦点与滚动 |
| 状态 | 加载、空状态、失败、重试、处理中、成功及结算信息 |
| 业务流程 | 会话切换、商品编辑、素材上传、Agent 选择、辅助、费用确认、生成、预览、下载、重生成与删除 |

动态字段与选项必须正确映射原型显示及真实接口能力；原型演示数值不构成生产配置。若真实接口无法满足原型字段或操作，先报告差异，不自行删掉或替换为技术字段。

### 5.2 原型交互执行清单

- 商品与个人资料默认展示摘要，编辑进入侧边抽屉；保存生效，取消或关闭不保存。按用户 2026-10-18 最新要求，生产右侧抽屉禁止 Escape 退出。
- 生成设置默认展示摘要，点击原位展开。
- AI 辅助建议可编辑、采用、取消与撤回，不自动创建生成任务。
- 任务、流水等详情按原型进入只读抽屉。
- 作品预览使用居中弹窗，只读预览提供关闭。
- 收费生成、重新生成及删除按原型展示确认，明示对象或费用。
- 弹层有焦点隔离，关闭恢复触发按钮焦点，长内容只滚动内容区域。
- 桌面创作工作台按 V2 三列构图；手机采用原型的单列顺序与历史会话入口。
- 任务快照、固定费用、会话草稿、作品来源与结算语义继续遵守需求，不因视觉整改发生变化。
- 后台编辑、配置、发积分、详情等沿用原型既定操作形式，不擅自增加全页裸表单。

上述清单仅作索引，不代替对应原型页面的逐项点击与字段核对。

### 5.3 不合理项处理机制

发现不合理项或冲突后，提交一条可供用户决策的记录：

| 编号 | 页面与原型位置 | 原型当前行为／字段 | 问题与触发条件 | 影响 | 用户改造计划 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 待新增 | 写明页面、截图或源码位置 | 客观描述现状 | 可复现，不用“体验差”代替说明 | 用户或实现影响 | 待用户提供 | 待处理 |

代理可以解释问题和约束，但不能把自己的建议标成用户确认的计划。未决项保留原型方案；阻碍实现的冲突标为待用户处理，其他无依赖项可继续。

普通布局溢出、对比度、焦点丢失等实现缺陷可按已有要求修复；如果修复会改变字段、操作含义、默认行为或流程，则先走上述处理机制。

## 6. 整改顺序与每阶段交付

| 阶段 | 工作 | 交付与进入下一阶段的条件 |
| --- | --- | --- |
| R0 已完成 | 手册与读取入口；独立首页高保真设计 | V3 稿及文案已展示，用户明确要求开始多 agent 实施 |
| R1 首页实施 | 按用户确认的首页稿落地布局、素材、注册登录入口与适当动效 | 实际桌面／手机截图、与稿件对照、主要入口可用；指出尚未实现或未批准内容 |
| R2 图片工作台 | 先核对原型字段与流程，再还原 V2 构图及组件 | 有成果、空状态、错误状态；字段与关键交互对照清单；未决原型问题已列出 |
| R3 其他用户页面 | 文案／视频工作台、作品、账户、充值、认证 | 每页按原型核对，复用已验证视觉组件，不自行改造 |
| R4 后台 | 用户／积分、Agent／规格、价格、任务、官网内容、审计 | 原型字段与操作逐项对齐，长表格与弹层可用 |
| R5 收尾 | 必要跨页流程与统一视觉检查 | 交互与视觉结果分别记录，未验项明确，不冒称生产验收 |

不得跳过首页高保真设计确认，直接批量改整站。不得把首页设计确认推定为非首页交互改造授权。

## 7. 验收规则

### 7.1 三类结论分别记录

| 类型 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 代码检查 | 类型、构建与适用行为检查 | 页面美观、设计还原、完整交互或上线可用 |
| 原型对照 | 实际字段、入口、操作及状态与原型一致 | 高保真视觉已还原或真实 Agent 已接入 |
| 视觉对照 | 真实页面在相同视口下与确认稿相符 | 权限、计费、持久化、业务总验收 |

### 7.2 视觉对照

- 使用同一视口对照设计稿与实际页面，检查首屏、比例、层级、留白、文字、边框、组件、素材及主要操作。
- 图片工作台既看空状态，也看有商品、有素材、有成果的状态；空壳截图不能作为完整还原证据。
- 首页检查首屏吸引力及整页浏览节奏，不能只有第一屏漂亮、后续内容粗糙。
- 桌面检查主要构图，手机检查内容顺序、触控、可读性及整页溢出。
- 高保真是构图与质感依据；所有图中文字与业务内容以登记文案、原型及需求为准。

### 7.3 交互对照

- 非首页每项改动关联原型中的字段或操作，逐项登记一致／不一致／待处理。
- 检查默认状态、点击后状态、取消、保存、错误恢复与移动端入口。
- 涉及费用、删除、账户身份与任务快照时，运行必要行为检查，不以截图代替。
- 不新增仅镜像实现、低价值或无关的测试；不因局部视觉修改重复运行整套后端矩阵。

### 7.4 控制重复工作

先完整实现当前页面，再集中查看桌面／手机及相关状态；将发现的问题集中修复，之后做一轮确认。有新增修改或失败再追加相应检查，不循环扫全站、反复随机换设计。

交付说明只报告实际完成、实际检查、尚存偏差和待用户处理项。未检查的内容不能写 PASS；本地演示、设计确认、功能检查与生产发布必须分开。
