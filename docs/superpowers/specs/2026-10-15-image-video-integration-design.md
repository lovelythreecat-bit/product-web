# 图片与视频 HTTP 接入设计

用户已选择：图片在工作台增加平台、用途选择；视频补充首帧选择及方案确认。此前接口核对见同目录 `2026-10-15-image-video-integration-assessment.md`。本文件将这些明确选择及既有计费规则落实为接口和实现边界；不修改上游项目、不执行收费生成或生产迁移。

## 配置

2026-10-16 用户确认的图片配置变更优先：图片后台仅展示文字模型（须支持图片输入）和图片生成模型的 API 地址、模型名称、只写 Key，生图保留 OpenAI Images / OpenRouter Images 协议选择。imageAgent 服务连接保留。原先暴露给管理员的 services/model-configs/agent-configs 及默认方案/别名选择由后端自动处理；旧资源代理接口保留兼容，但不再作为图片页面操作入口。GET/PATCH `/api/v1/admin/media-agents/image/models` 将两类模型映射到上游独立资源，使用连接 revision 和相关上游 version 防止陈旧保存。Key 留空仅复用相同 API 地址、协议且启用的已配置供应商服务；首次配置、更换地址/协议须新 Key。保存不原地修改旧资源，全部新资源建立完成后再激活版本化连接；两类模型分别绑定 `stages.vision` 与 `image_models.fast`，其他文字阶段复用 vision，原运行参数保留。失败不激活半套配置，可能留有未被引用的上游资源；不自动删除或调用生成。模型和供应商 Key 仍唯一归上游，不增加本地模型副本或数据库迁移。视频配置及下文任务、计费与恢复边界保持原约定。

后台沿用文本/图片/视频切换和编辑抽屉。web 加密保存独立的图片、视频服务连接，版本化保留连接以恢复历史任务；视频区分业务与管理 Token。模型与供应商密钥只存上游，web 代理其实际资源，不复制模型配置。图片按上方最新两类模型配置执行；视频管理 adapter-types/model-profiles/adapter-bindings/settings，分别使用实际资源版本。所有写操作须管理员、CSRF、审计，响应和错误不泄密；打开编辑自动读取最新值，409 保留草稿并提示重新打开。

## 工作台

图片选择一个目标平台和一个用途，初始不替用户选值；用途使用实际上游枚举 main_image/detail_page/pdd_white_background/long_image，并验证组合（白底仅拼多多）。商品分类、商品图为必填。多图或详情用途继续受既有 D-04 完整交付门槛约束，不擅定部分成功收费。按类型积分/次不变；这些是输入字段，不恢复规格价格管理。

视频从已上传商品图中显式选择首帧，不自动选第一张。任务先规划；卡片明确显示补充资料、待确认方案或生成进度。方案用现有抽屉呈现具体内容，用户点击确认后以固定 plan_version 提交，方案确认不重复冻结积分。补充资料是原任务下的显式、持久命令，不改写原受理快照。刷新读取原任务及持久交互阶段，不自动 confirm。

收费沿用提交时冻结、完整成果保存后消费、确定失败释放；等待用户期间维持冻结，不引入取消、超时自动退款、自动重试生成或新的部分交付政策。费用确认明确视频先规划且需要用户继续确认，防止误认为一次点击即可完成。

## 执行与恢复

新增媒体执行记录，保存已上传素材映射、精确提交 body、上游阶段及 task/plan/generation/artifact 身份。上传和网络调用在数据库事务外，写回受任务身份/租约约束；受理快照保持不变。命令先持久化，再调用上游，原键同参恢复，异参冲突。

图片服务无按外部键查单，丢失 task_id 且无可靠保留作用域证据时保持待核查，禁止自动重 POST；已有 task_id 轮询原任务。视频按 external_request_id 精确查找，验证本地原身份，多匹配不任选。404、超时和不确定状态不是失败证明。

图片 completed/blob 不代表合格；只对已定义的预期目标、审核通过、完整资产建立成果，部分/待审核/人工接受未批准不结算。视频按精确 task+plan+generation 选择成片，不取列表第一条；未通过的质量状态不认定成功。受控下载计算摘要和长度，实际校验内容、完整落盘，复用现有原子发布和结算。

上游未提供提交时 expected_config_version；图片提交和视频规划/确认分别取其有效配置快照。web 固定连接与配置引用，并保存上游版本事实，不能声称本地预读版本能消除提交窗口。真实生成仍受既有确认政策、价格与容量门槛控制；不自动配置或打开生产门槛。

## 并行边界与验收

图片适配、视频适配、后台配置三任务并行，分别写独立模块；共享 registry、受理、报价、结果及工作台由主控单一写入。实现后独立评审。测试至少覆盖配置版本/秘密投影、输入组合/首帧绑定、稳定上传映射、状态及确认幂等、错任务/方案/成果拒绝、原结果恢复和原价格保持；完成类型检查、构建和实际桌面/手机界面核对。
