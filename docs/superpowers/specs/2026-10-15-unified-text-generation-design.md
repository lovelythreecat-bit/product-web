# 文本生成统一使用后台配置

> 同日后续用户要求已删除生成规格与「规格与价格」入口，现行计价流程见 [按类型计价](2026-10-15-simple-generation-pricing.md)。本文保留文本服务与默认模型决策，规格/价格流程描述为历史。

日期：2026-10-15。状态：用户已批准并要求执行；实施及复核完成，见[验证记录](../../verification/unified-text-generation-2026-10-15.md)。

## 用户已确定的目标

删除管理后台「文本服务接入」及其独立配置流程，创作工作台文本生成直接使用现有「服务连接设置」和「文本模型配置」。多个模型时由管理员指定一个默认模型，工作台不新增模型选择步骤。这覆盖原设计中“本次不改变生成绑定”的限制。

## 当前实现及本机证据

- 管理接口已经逐次读取 web 数据库中的文本服务地址和加密服务 Key，模型配置和模型 Key 唯一保存在 textAgent。
- 生成任务仍通过 AgentRecord.secret_ref 查找 APP_TEXT_AGENT_PROFILES，使用其中另行填写的地址、Key 和模型 ID；只删页面不能消除该依赖。
- Agent、规格、报价、冻结积分和任务快照相互关联，不能直接删除底层表或跳过报价链路。
- 本机目前有一个启用模型 abc / deepseek-v4-pro；平台 Agent、规格、价格列表均为空。模型保存成功不等于生成已可用。

## 选定方案

将现有调用链改为数据库服务连接加默认模型，保留任务及计费结构。相比继续同步环境 profile，该方案消除重复配置；相比拆除全部目录、规格与计费逻辑，改动集中于文本路由，符合此次目标。

### 后台入口与默认模型

1. 从 AgentsView 删除「文本服务接入」列表、新增按钮、Agent 编辑抽屉及文本 Agent 发布交互，清理其专用状态和调用代码，不以 CSS 隐藏。保留规格与价格页面及其必要的内部 Agent 标识。
2. 在现有文本模型列表增加默认标记和「设为默认」操作，沿用现有按钮、原因输入和审计方式，不增加另一套服务连接表单。
3. web 仅保存默认模型 UUID、偏好 revision、修改人和时间，不保存模型参数或模型 Key 副本。设置默认时校验模型属于当前服务身份且启用、已配置模型 Key。
4. 默认选择为显式设置，不按列表顺序、最新创建或首个启用模型推断。初次实施时将用户目前指定的 abc 模型设置为默认。
5. 更新默认模型保留管理员、CSRF、expected_revision、原因和脱敏审计。校验期间连接变化则拒绝提交，不能把旧服务的模型绑定到新服务。
6. 更换服务 origin 时清除默认选择；同地址轮换 Key 后重新校验模型访问。默认模型被停用、删除或不可访问时，清晰提示配置问题，不悄悄切换模型。

### 工作台和任务调用

1. 文本生成能力使用服务端维护的内部稳定 Agent 身份关联规格、报价和任务，管理员无需填写 Agent 端点、profile 引用、协议版本等接入字段。旧的手动文本 Agent 发布流程不再作为新文本生成的配置入口。
2. 新任务受理时读取数据库服务连接和默认模型，向 textAgent 获取其当前可用性与图片能力；使用现有已实现文本协议及输入映射，保持规格、价格、积分、存储和并发校验。
3. API 与 Worker 共用该数据库解析逻辑；新文本任务完全不依赖 APP_TEXT_AGENT_PROFILES，也不通过旧环境配置回退。
4. 受理前验证映射和图片限制。服务或默认模型不可用时，在创建任务、冻结积分之前失败；不发送生成请求来测试配置。
5. 任务路由快照固定服务 origin、模型 UUID 和图片能力，避免切换默认模型影响已提交任务。不把服务 Key、模型 Key 或密文加入任务快照、审计或响应。
6. Worker 执行、查询与恢复沿用原任务绑定，不重新选择当前默认模型。当前连接无法访问原服务或原资源时进入现有异常处理，不把原任务转交新服务，也不自动重新生成。
7. 不破坏历史任务、作品、账本或审计外键。清理新任务配置依赖与物理删除历史事实分开处理；若存在历史环境 profile 任务，升级必须显式识别并报告其兼容限制。
8. textAgent 服务 Key 的生成链路需要 generate 与 records:read 权限；只有 configs:read / configs:write 的 Key 仅能管理模型。联调前核验当前 Key 权限，凭据不通过聊天或日志传递。

### 规格与价格

继续使用现有「规格与价格」入口维护积分价格和输入参数。内部文本 Agent 由服务端维护并供规格关联，用户不再经过已删除的文本接入表单。现有缺失的商业价格、容量和开放规则不得凭空补成生产默认，也不得以删除接入配置为由取消收费确认。

## 验证与完成标准

- 前端：旧文本服务接入及表单代码删除；模型列表可设置默认，刷新后保留；权限、版本冲突与失败状态正确；工作台没有额外模型选择步骤；类型检查和构建通过。
- 后端：默认选择落库、跨服务冲突、停用模型、密钥只写、管理员和 CSRF 检查通过；环境 profile 为空时新文本任务仍能解析数据库连接。
- 受控 HTTP 加隔离 MySQL：验证受理、Worker 实际请求使用当前数据库 Key 和指定默认模型，切换默认后旧任务仍请求原模型，失败不重复生成、不错误冻结或结算。
- 真实页面：删除入口可见性、默认设置持久化、工作台读取统一配置。当前没有规格和价格，真实收费生成的验证必须在其明确配置后进行，不能以模拟测试代替。
- 更新产品设计入口及部署文档，移除“生成仍需另填 profile”的现行说明，历史验证记录标注被替代范围。

## 实施边界

沿用已确认的 V2 暖色组件，不调整首页、图片或视频接入。此次不创建新的第三方模型凭据，不改变 textAgent 模型数据归属，不发布生产环境，不删除历史业务数据。
