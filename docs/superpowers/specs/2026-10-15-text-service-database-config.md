# 文本服务配置的最终数据归属

日期：2026-10-15。状态：用户已确认，以本文件当前内容替代同路径的已撤回双写草案。

> 后续变更：用户已批准[文本配置统一](2026-10-15-unified-text-generation-design.md)，生成任务也使用数据库服务连接及后台默认模型；下文关于“不自动修改生成 profile/绑定”的内容仅记录当时范围，不再作为新任务配置规则。

## 已确认方案

用户撤回“模型配置同时保存到 web 与 textAgent”的要求，并确认按职责保留唯一数据来源。

| 数据 | 权威存储 | web 的职责 |
| --- | --- | --- |
| 文本服务地址、服务访问 Key | web 自己的 MySQL | 后台配置；Key 加密保存；后端每次读取连接并调用 textAgent |
| 模型名称、厂商地址、模型 Key、能力、参数及模型启停 | textAgent | 通过服务端代理调用 textAgent 的 GET / POST / PATCH；不另存模型表或模型 Key |
| 平台 Agent、规格、积分价格和开放状态 | web | 保留现有业务版本与发布流程；模型引用与历史快照不构成可编辑模型副本 |

管理页面 → web 同源 API → textAgent API → textAgent 返回模型配置。查询直接使用上游数据，不使用本地模型缓存。远端写入失败不得显示成功，网络不明确时不自动重发写入。

## 本次实施范围

1. 新增 web 数据库 `text_service_connections` 单例记录，迁移预置未配置行以序列化首次并发写入。
2. 提供管理员 GET / PATCH `/api/v1/admin/text-service-connection`，保留 CSRF、版本校验、修改原因和脱敏审计。
3. 服务 Key 使用 Fernet 认证加密，密文绑定用途与服务 origin。主密钥只放后端环境，不与密文存于同一数据库。
4. GET 仅返回地址、Key 是否已配置、revision 和更新时间；编辑留空保留旧 Key，更换地址必须显式提供 Key，避免把旧凭据发给新服务。
5. 复用 Agent 文本分类中的既有暖色抽屉。保存连接后刷新模型列表，后续管理请求立即读取数据库，无需再次重启。
6. 模型管理沿用既有远端代理，模型数据不在 web 落库，模型 Key 只转发。服务地址或凭据不再从管理环境配置或生成 profile 隐式回退。

本次仅使现有模型管理使用数据库连接，不自动改写生成 profile、任务模型绑定、已受理任务快照、收费政策、图片或视频接入。

## 部署与失败行为

- 首次部署执行 `0024_text_service_connection` 并配置持久的 `APP_TEXT_SERVICE_ENCRYPTION_KEY`，随后重启 API 一次。日常在后台修改服务连接不再重启。
- 缺少或无法使用加密主密钥时拒绝写入或使用密文，不能回退成明文或旧环境凭据。
- 连接保存成功仅代表本地设置保存，不保证上游 Key 已被授予配置读写权限。
- textAgent 模型创建没有幂等参数，写入不自动重试；生成接口的幂等能力不得套用到模型创建。
- 未得到可用服务 Key 不签发新身份、不创建真实模型、不触发真实生成。

## 验收

单元检查加密、留空保留、地址更换、版本冲突、权限和 CSRF；使用隔离 MySQL 与受控 HTTP 验证本地连接持久化及远端模型接口调用；验证桌面和手机的抽屉、焦点、保存和关闭。实际证据见[本次验证](../../verification/text-service-connection-2026-10-15.md)。
