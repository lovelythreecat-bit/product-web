## 2. 产品定位与边界

用户围绕商品资料，在统一窗口中调用文案、图片、视频 Agent。平台帮助用户准备创作指令，展示任务状态，保存并管理生成成果。

平台负责账户、权限、会话、素材、任务、作品、积分和配置管理。Agent 服务负责各自的生成能力。

首版提供三个 Agent 的独立调用和统一呈现。自动判断应使用哪个 Agent、多 Agent 自动串联、批量生成、团队协作和电商平台自动发布，安排在后续阶段。

## 3. 角色与权限

| 角色 | 主要权限 |
| --- | --- |
| 访客 | 浏览宣传首页，进入注册与登录页面 |
| 普通用户 | 管理个人资料，使用 Agent，优化创作指令，查看自己的会话、素材、任务、作品和积分流水 |
| 管理员 | 管理用户，发放积分，配置 Agent、生成规格与价格，查询任务异常，维护官网内容，查看操作记录 |

用户数据按账户隔离。后端对每次会话、任务、文件和作品访问校验权限，文件链接同样受权限保护。

管理员查询任务异常默认查看必要的状态与错误信息；查看、预览或下载用户素材、作品和消息内容须具备单独授权，并记录操作人、对象、时间和访问原因，不能因拥有普通后台权限而默认访问全部用户内容。

账号密码注册保持简单；后端仍需进行账号唯一性校验、密码安全哈希和基础接口限流。这些属于实现要求，不增加额外注册步骤。

管理员调整积分、修改价格和重要配置等操作需要留存操作人、时间和变更内容。

账户停用后，禁止新登录和新提交任务，并使已有会话失去受保护接口的访问权限。已有任务、冻结积分及已存作品仍保留记录，不因停用直接删除或重复结算；已有任务继续执行还是终止处理、恢复账户及作品访问政策待确认，不能假定上游支持取消。

密码只保存安全哈希，不回传密码或哈希。Agent 凭据等秘密由服务端保存，配置查询只返回脱敏状态；操作日志和任务错误信息不得记录完整凭据。

## 5. 统一创作窗口

### 5.1 页面结构

- 左侧：会话列表、新建会话、我的作品入口。
- 主区域：用户输入、生成任务卡片和结果记录。
- 输入区域：Agent 选择、文字要求、素材上传、规格设置、“AI 帮我完善”和“生成”。
- 积分区域：可用积分和“充值积分”入口。

输入项和规格随 Agent 选择变化，仅展示当前 Agent 实际支持的选项。

### 5.2 共用流程

1. 用户注册，获得一次试用积分。
2. 新建会话，选择文案、图片或视频 Agent。
3. 提供商品资料、创作要求和所需素材。
4. 按需使用 AI 辅助生成／完善创作指令，预览并编辑。
5. 选择生成规格，查看本次所需积分。
6. 点击生成，平台持久化任务和本次输入快照，并冻结对应积分；重复提交同一次请求返回同一任务。
7. 文案按接口能力临时流式展示；图片和视频展示任务状态，完整结果保存后出现正式成果。
8. 完整结果及作品保存完成后，任务成功并扣除积分；确定失败后释放冻结积分。状态不明时显示“待核查”，保存异常时显示“保存失败，待恢复”，不据此重新生成或结算。
9. 用户可以复制、预览、下载或重新生成。

聊天界面保存历史，但正式生成以用户提交时确认的资料、素材、指令和参数为准。每个任务固定所选 Agent 及接入版本、商品资料、素材版本、创作指令和参数快照；之后切换 Agent、编辑资料或修改配置，只影响后续提交，不能串用到进行中的任务。首版不依赖 Agent 多轮修改能力，不自动将整段会话作为每次任务的输入。

流式片段只用于临时展示，不作为最终作品或计费成功依据。关闭页面、SSE 断线和刷新不驱动任务取消、失败或重提；重新进入后读取服务端持久化的任务、消息和完整结果。中间片段是否支持续传待接口确认，未保存的片段不保证恢复。

“重新生成”创建新任务、重新按规格计费，原结果保留。用户提交前必须能够看到费用。

## 6. 三个 Agent 的功能范围

### 6.1 文案 Agent

- 输入：商品基本资料、可选创作要求、可选商品图片。
- 输出：通用电商文案。
- 范围：首版不做视频脚本等专项功能，也不要求复杂的文案分类入口。
- 参数：先提供通用项，具体字段待接口确认；可考虑长度、语气和生成份数等常见设置。
- 呈现：优先采用流式输出，具体能力待 Agent 接口确认。
- 修改：不满意时重新生成，不要求基于上一次结果进行局部或连续修改。

### 6.2 图片 Agent

- 输入：商品图片 + 文字要求。
- 输出：支持商品主图、场景图、详情页图片和海报。
- 首版常见参数：图片比例、尺寸／分辨率、生成张数、画面风格。
- 扩展方式：其余参数后续增加；可选值与约束按 Agent 实际能力配置。
- 修改：重新生成整张图片，首版不做区域编辑。

“详情页图片”在本文中指图片生成用途，不自动扩展为完整长详情页排版编辑器；最终产物形态和张数规则待接口确认。

### 6.3 视频 Agent

- 输入：商品文字介绍和商品图片。
- 输出：可以直接播放、下载的视频文件。
- 用户选择参数：时长、横竖屏、分辨率、配音、字幕和背景音乐。
- 规格：具体时长档位、分辨率、声音和音乐选项按 Agent 实际支持范围配置。
- 修改：重新生成整个视频，首版不做镜头或局部编辑。

商品文字介绍与商品图片是否都必须提供，以及图片数量和大小限制，待 Agent 接口确认。

## 7. AI 提示词辅助

输入区域提供“AI 帮我完善”，支持两类场景：

1. 用户已有简单描述，平台将其整理成适合当前 Agent 的指令。
2. 用户提供商品资料后，平台协助生成初始创作指令。

辅助功能结合用户描述、商品资料、所选 Agent 和可用素材进行处理。

| Agent | 指令整理重点 |
| --- | --- |
| 文案 | 表达目的、受众、语气、内容结构和长度要求 |
| 图片 | 构图、背景、光线、主体、画面风格及参考素材关系 |
| 视频 | 画面内容、镜头与节奏要求，以及用户已选择的视频规格 |

要求：

- 保留用户原始描述，允许编辑、撤回和重新优化。
- 不凭空补充商品材质、功效、价格、优惠或其他事实。
- 缺少必要信息时提示用户补充。
- 辅助功能只准备指令；用户点击正式生成后才创建业务生成任务。
- 视频指令中的镜头描述用于准备 Agent 输入，不意味着新增独立脚本创作功能。

建议提供单独的有限免费次数，由后台配置；是否采用该方案、辅助额度政策及实现方式按 D-05 确认，采用时再明确次数、扣减与重置规则。

## 8. 积分与计费

### 8.1 首版积分来源

- 注册赠送：每个新账户获得一次试用积分，数量可配置。
- 管理员发放：记录接收账户、数量、操作人、时间和原因。
- 首版不接入真实支付；管理员发放和注册赠送不能被统计为支付收入。
- 积分账户分别记录可用积分、冻结积分和累计已消费积分。在首版仅赠送／发放和消费的范围内，三者之和等于累计入账积分，均不得为负数。冻结将可用积分转为冻结积分；结算将冻结积分转为已消费积分；释放将冻结积分返还可用积分。

### 8.2 定价规则

采用按生成规格明码标价。具体价格由后台配置，前端在提交前展示。

| Agent | 可配置计费维度 |
| --- | --- |
| 文案 | 通用规格／长度档位、生成份数，最终依据接口确定 |
| 图片 | 图片用途或规格、尺寸／质量、生成张数 |
| 视频 | 时长、分辨率，以及实际需要影响价格的可选项 |

前端展示当前规格、报价及其规格／价格版本，提交时携带用户确认的版本和费用；服务端独立校验。版本失效、规格下架或报价不一致时，不创建任务、不冻结积分，返回当前可用规格与报价，供用户重新选择并确认后提交；不得静默改用新价格扣费。

每个受理的任务保存用户确认的规格、规格／价格版本和固定费用。管理员修改规格或价格后，已受理任务继续使用该快照。

平台内部记录供应商实际用量和成本，用于核算和后续调价，不改变本次按规格确定的费用。

多结果规格（如多份文案、多张图片）须先确定部分成功、结果缺失及部分保存失败时的交付与计费规则；未确认前不得上架对应规格。建议优先考虑整单全部成功并保存后扣费，否则整单释放；此建议尚未确认，不作为既定政策，也不得由实现自行选择按张扣费。

### 8.3 消费流程

1. 服务端识别本次提交意图，校验用户确认的规格和报价，检查可用积分。
2. 在同一数据库事务内创建任务、冻结固定费用并写入积分流水。余额不足或任一步骤失败时全部回滚，不留下任务或冻结记录；事务提交后才允许派发上游任务。
3. 符合已确认成功条件且作品保存完成后，将冻结积分结算为已消费积分。
4. 任务确定失败后，将全部冻结积分释放回可用积分。

积分不足时不能提交任务。超时或上游状态不明时先核查原任务；已生成但保存失败时优先恢复原结果的保存，不能仅因超时或保存失败认定上游生成失败并重新调用。

待确认异常处置政策：设置可配置的核查期限，长期状态不明或保存无法恢复的任务在期限届满后必须进入管理员处理，不能无限期冻结。管理员按届时确认的政策人工结算或释放，并记录证据、原因、操作人和时间，用户能够查询处置原因；没有符合成功条件且作品已保存的证据不得结算，期限届满本身不代表上游失败。已人工处理的任务收到迟到结果时保留记录，不自动追加扣款；核查期限、释放依据及迟到结果的交付方式须在上线前确认。

余额、冻结金额与积分流水以 MySQL 为准，通过数据库事务处理并发消费。注册赠送、管理员发放、冻结、结算和释放均须幂等；同一任务的结算与释放互斥，只能完成其中一种，重复通知、重试及人工操作不得重复扣款、释放或入账。每次账户变更与对应流水必须原子提交，失败完整回滚。

双击、网络重试等同一次提交复用同一提交标识，仅返回原任务且只冻结一次；同一标识携带不同生成内容、规格或报价时拒绝受理。用户主动“重新生成”使用新的提交标识，按新报价确认并创建新任务。平台自身的去重不依赖 Agent；上游重复派发的防护仍需结合 Agent 幂等及状态查询能力，状态不明时不得盲目重发。

积分流水至少记录业务类型、金额、变更前后可用／冻结／已消费积分、关联任务或发放操作、时间和必要说明，能够核对账户守恒及每笔冻结的最终去向。

## 9. 充值入口与后续支付

### 9.1 首版入口

- 统一工作台积分区域和个人中心提供“充值积分”。
- 点击打开充值说明页，展示当前积分。
- 提示在线充值暂未开放，微信／支付宝后续接入。
- 不创建支付订单、不调用支付渠道、不增加积分。

### 9.2 后续真实充值

后续增加充值金额选择、支付订单、微信／支付宝支付、服务端验签及核验、支付状态查询、到账和退款处理。

支付成功后通过积分入账流程发放积分，复用首版消费机制。支付通知重复到达时，只能入账一次。

人民币兑换比例、充值档位和退款规则属于后续支付阶段的待确认事项。

## 10. 技术架构建议

```text
Vue3 + TypeScript 前端
          │
Python FastAPI 平台后端
  ├─ 账户、权限、会话、作品、积分、配置
  ├─ AI 提示词辅助
  ├─ SSE 流式输出与任务状态通知
  └─ Agent 接入层
       ├─ 文案 Agent 服务
       ├─ 图片 Agent 服务
       └─ 视频 Agent 服务

MySQL：业务数据、任务、积分账本
Redis：缓存、限流、任务队列支持
后台 Worker：异步任务执行、状态同步、结果保存
服务器硬盘：上传素材和生成作品
```

FastAPI、SSE 和 Celery 等成熟任务框架是建议实现选型。平台后端初期保持一个业务项目，三个 Agent 独立部署与迭代。

平台接入层统一处理各 Agent 的差异。Agent 需要约定输入格式、任务标识、状态、完整结果、错误信息和用量信息，并确认是否支持提交幂等标识、按平台外部标识查找任务、按上游任务标识查询状态。

MySQL 是任务与积分的事实来源。任务、冻结积分和待派发记录须在同一事务内持久化；Redis 投递失败、消息丢失或 Worker 重启后，后台依据持久化记录恢复派发和处理。Redis 队列仅承载调度，不能成为任务唯一记录；具体采用事务消息表或其他可恢复派发方案在实现时确定。

Worker 领取与更新任务须有持久化的并发防护和中断恢复机制，按已记录的处理阶段继续。平台在调用上游前记录本次提交标识，取得上游任务标识后及时持久化。队列重投不能直接等同于再次请求上游生成：仅在 Agent 支持可靠的上游幂等提交或按外部标识查询并确认可重试时，才允许自动安全重试；提交超时且无法确认是否已受理时，进入待核查，禁止自动再次生成。

文案流式输出及取得最终完整文案的方式尚需接口确认。SSE 是前端展示与通知通道，任务执行和结果保存独立于连接生命周期。图片和视频优先按后台任务处理，根据接口能力通过回调或轮询获取状态和结果。

Agent 服务之间的调用及回调均需鉴权，具体签名或凭据协议待确认。回调须验证来源、防重放，并核对 Agent 服务与已绑定的上游任务标识（或可验证的平台外部标识）；用户归属从平台任务记录读取，不接受回调任意指定用户或任务。无法对应的通知留存异常记录，不更新业务任务。模型密钥和服务凭据由服务端管理。

## 11. 本地文件存储

- 上传素材和生成作品保存到服务器硬盘。
- 服务端生成随机文件标识并按账户隔离存储目录；用户文件名仅用于展示，不接受用户指定路径或使用其文件名拼接存储路径。
- MySQL 保存文件标识、所属用户、内部存储路径、实际类型与大小、删除状态，以及与作品、历史消息、任务输入和结果的引用关系。
- 文件下载与预览经过用户权限校验，不直接公开整个存储目录。
- 上传和 Agent 结果保存均校验实际文件格式和大小，不能只信任扩展名、声明的类型或长度；对超限、不支持或内容与声明不符的文件拒绝保存并返回明确原因。
- 上传前检查账户配额和服务器可用容量；生成前按规格及全部预期结果文件估算并预留容量，防止并发任务重复占用同一剩余额度，保存后按实际大小核算和释放剩余预留。任务终结或受理失败后，幂等回收未转为实际文件占用的预留；待核查任务的预留期限结合异常策略待确认。多文件结果的估算规则、单文件限制、账户配额及容量预警阈值待确认。
- 容量不足时拒绝新上传或新生成。上游已生成但保存失败时保留原任务和结果定位信息，恢复容量后仅重试原结果的下载与保存，不自动再次生成或重复扣费；结果链接有效期、暂存期限及无法恢复时的处理待接口和产品确认。
- Agent 返回临时结果链接时，由后台及时获取并保存成果。下载仅允许配置并核准的 Agent 结果来源，校验目标主机、解析地址及每次重定向，拒绝回环地址、云元数据地址和未授权内网地址；设置下载体积、时限和重定向次数上限。不得直接抓取任意用户提交的 URL，具体来源和限值待接口确认。
- 作品删除与文件物理清理分开处理。记录逻辑删除状态和引用关系，保留任务与积分记录；物理删除仅在不再被需要保留的消息、任务或作品引用且满足保留规则时执行。删除后作品库、历史消息及下载入口的展示、能否恢复、是否计入容量和具体保留期限待确认。
- 排队、执行和结果保存中的任务引用的素材不得删除或提前清理。重新生成提交时校验原素材仍存在且有访问权限，缺失时提示重新上传；素材引用快照和必要文件保留到任务处理完成。
- 文件类型、大小、账户容量和保留规则可配置，具体数值待定；未确定保留规则前，不执行会破坏已有引用的自动物理清理。
- 部署时设置持久存储目录、基础容量监控和备份，避免更新应用覆盖作品文件。

可保留简单的文件存储接口，方便以后替换为云对象存储；首版不要求接入云存储服务。

## 13. 核心数据与可靠性

核心数据实体包括用户、会话、消息、商品资料、素材文件、Agent 配置、生成规格、价格版本、生成任务、作品、积分账户、积分流水和管理员操作日志。

任务状态基线（语义固定，状态码由实现设计映射）：已提交、排队中、提交上游中、执行中、待核查、结果保存中、保存失败待恢复、成功、失败、人工关闭。待核查和保存失败待恢复均为未结算状态，不能作为确定失败；超时本身不证明上游失败。人工关闭用于按第 8 节核查和结算规则完成有审计的异常处理，不表示已确认上游生成失败。

任务至少持久化平台任务 ID、所属用户与会话、用户提交幂等标识、不可变输入快照、Agent 服务及接入版本、平台外部提交标识、上游任务 ID、处理阶段、状态、价格快照和结算记录。上游任务 ID 在对应 Agent 服务范围内绑定唯一平台任务；素材快照引用可保留且不可覆盖的文件版本。凭据不写入输入快照。

基础要求：

- 同一用户以相同提交幂等标识和相同输入重试，只返回原平台任务，不重复冻结；相同标识携带不同输入须拒绝。主动重新生成使用新标识创建新任务。
- 任务与冻结事务提交后，即使 Redis 投递失败或 Worker 在任一阶段重启，仍可从 MySQL 恢复派发、查状态或保存结果；恢复时不得盲目重提上游生成。
- 上游支持可靠幂等提交或按外部标识核查时，按已确认能力恢复；缺乏这些能力且提交是否受理不明时，保留原标识和调用证据，进入待核查并提供后台人工核查入口。确认前不再次生成、不自动释放或扣除冻结积分；人工处理记录依据、操作人和时间。
- 已取得上游任务 ID 后，按接口能力查询同一任务或等待可信回调，无法查单不构成自动重提的理由；已生成但保存失败时，恢复下载和保存原结果。保存失败待恢复须记录原结果位置、失败原因和恢复记录，不能通过重新生成冒充保存恢复；链接失效且无法恢复时转待核查处理。
- 完整文案及最终消息、或约定规格的完整图片／视频成果和作品记录，均持久化成功后才标记成功并结算。暂存流式片段、上游“成功”通知和临时结果链接均不足以判定平台任务成功。
- 页面刷新、关闭和 SSE 断线不改变后台任务状态；重新进入从持久化任务、消息和作品恢复展示，不能因此再次创建任务。
- 重复、乱序回调与轮询结果只更新其对应任务，按允许的状态迁移去重处理，不能将结果保存中退回执行中。成功、确定失败和人工关闭为终态；迟到通知不得逆转终态、重复扣款或释放。人工释放后的迟到成功仅登记异常并交后台核查，不自动补扣积分。
- 记录任务错误、耗时和成本，配置基础监控和数据库备份。
- 对注册、提示词辅助、文件上传和生成接口设置基础限流。

### 13.1 任务状态与结算约束

任务状态表示处理进度，结算状态单独持久化为“冻结中／已消费／已释放”。状态变更采用持久化并发校验；不能仅用 UI 文案或 Redis 锁保证正确性。下表细化第 8 节和本节既有规则，不新增人工扣款或取消政策。

| 当前阶段 | 允许的后续方向 | 必须满足的条件 |
| --- | --- | --- |
| 已提交／排队中 | 排队中／提交上游中；确定失败时进入失败 | 已有任务、冻结和待派发记录；派发前保留提交标识；只有确定失败才能释放 |
| 提交上游中 | 执行中／结果保存中／待核查；确定失败时进入失败 | 收到可验证受理、最终结果或确定失败证据；受理不明转待核查，不能默认再次调用 |
| 执行中 | 结果保存中／待核查；确定失败时进入失败 | 查询／回调对应已绑定任务；暂时查单失败不得重发生成 |
| 待核查 | 依据证据恢复执行中／结果保存中；符合第 10 节安全重试条件时恢复提交上游中，需调度时先回排队中；或确认失败、按已确认异常政策人工关闭 | 按已确认接口能力及可靠幂等提交或外部标识可靠核查证据确认可安全重试；沿用原平台任务、外部提交标识和输入／价格快照，不新增任务或冻结；已有上游任务 ID 时优先查原任务；暂未查到不等于可靠证明未受理，无法证明安全时继续待核查；进入该状态不结算、不释放，保留核查证据及责任记录 |
| 结果保存中 | 成功／保存失败待恢复 | 完整成果及作品、最终消息（适用时）保存完成后才能成功并结算；仅有临时链接不足以成功 |
| 保存失败待恢复 | 结果保存中／待核查；按已确认政策人工关闭 | 仅恢复原结果保存；链接失效且无法恢复转待核查；不重发生成、不重复冻结 |
| 成功／失败／人工关闭 | 保持终态，仅追加审计与冲突记录 | 成功对应已消费；失败对应已释放；人工关闭仅在第 8 节政策允许且完成唯一结算／释放后进入，不意味着上游失败；迟到事件不逆转、不补扣 |

同步接口可以从提交上游中直接进入结果保存中；可明确证明从未受理或已失败的任务不必先进入执行中。任何捷径都不能绕过完整交付、幂等和积分事务。状态冲突进入异常记录，不根据乱序事件倒退已完成阶段。

成功入库的最低边界：最终成果、作品／最终消息关联、任务成功状态、积分结算和对应流水具备可恢复一致性。文件写入与数据库无法共用事务时，先完成并校验文件持久化，再由数据库事务发布作品、成功状态与积分结算；中断后通过保存记录恢复或清理孤立文件。已经有本地完整成果但数据库提交失败时恢复入库，不重新生成。具体文件落盘与恢复方案由实现设计明确。

## 14. 首版验收标准

验收项采用 AC 编号，测试记录须保留使用的 Agent 接入版本、规格／价格版本、配置、任务标识和相关证据。下表是需执行的验收要求，不是已通过的结果；含待确认政策的场景，在第 15 节对应确认完成后按其版本执行。模拟验证与真实联调结果分别记录。

| 编号 | 场景与操作 | 可核对的预期结果 |
| --- | --- | --- |
| AC-01 | 账号密码注册、登录、退出；同一注册请求重试 | 无手机号或邮箱前置验证；账号唯一，密码仅保存安全哈希；同一账户试用积分只入账一次；退出后当前登录凭据不可继续访问受保护接口 |
| AC-02 | 管理员配置 Agent、规格、价格；按相同发放业务标识重试发放 | 服务与配置可管理；凭据只返回脱敏状态；积分发放只入账一次，有原因、操作人、时间和完整流水 |
| AC-03 | 在统一创作窗口分别选择文案、图片、视频并提交合法输入 | 分别绑定所选 Agent 和输入快照；成功得到完整文案、可预览图片、可播放视频；只展示实际支持的参数 |
| AC-04 | 用商品资料完善指令，编辑、撤回、再次优化 | 原描述可保留和恢复；不添加无依据的商品事实；用户正式点击生成前不创建业务生成任务；按 D-05 已确认的辅助额度政策验收，仅在确认采用独立免费配额时核对次数扣减与重置 |
| AC-05 | 查看规格费用后，后台调价、修改规格或下架，再提交旧报价 | 服务端独立核价；旧报价失效时不创建任务、不冻结积分，返回当前可用报价；用户重新确认后才受理 |
| AC-06 | 积分不足、并发提交、事务中断、容量不足 | 不足时不受理；任务、冻结和流水原子成功或回滚；可用／冻结／已消费均不为负；生成前校验并预留容量；受理失败回收未使用预留 |
| AC-07 | 同一提交标识重复点击或网络重试；同标识改变输入 | 相同内容返回同一任务且冻结一次；不同内容拒绝，不创建第二任务；用户主动重新生成使用新标识、新报价并保留原成果 |
| AC-08 | 提交后编辑商品资料、切换 Agent、修改参数和配置 | 原任务保持提交时的资料、素材版本、指令、Agent 接入版本、规格／价格与费用快照；仅后续任务使用新配置 |
| AC-09 | 取得流式片段、仅有上游成功通知或临时结果链接 | 可展示进度，但完整结果、作品及所需最终消息未持久化前不得成功或结算；文案流式按已确认能力降级或启用 |
| AC-10 | 完整成果保存成功；确定失败；重复或并发结算／释放 | 成功交付后冻结转消费；确定失败后冻结转可用；同一冻结结算与释放互斥且各只执行一次；账户与流水守恒 |
| AC-11 | 事务提交后队列投递失败、消息丢失，Worker 在关键阶段重启 | MySQL 仍保留任务与待派发／恢复记录；恢复同一任务，按已有阶段处理，不盲目重提上游生成 |
| AC-12 | 上游提交响应丢失或超时；待核查后取得安全恢复证据或仅暂未查到任务 | 按已确认可靠幂等／核查协议恢复原任务；证据确认可安全恢复原提交时，进入提交上游中（需调度时先回排队中），复用原外部提交标识及输入／价格快照，只有一个平台任务、一次冻结和一个有效上游生成意图；已有上游任务 ID 时优先查原任务；暂未查到不等于可靠证明未受理，无法证明安全时继续待核查，不重发生成、不自动结算或释放 |
| AC-13 | 已知上游任务 ID，轮询暂时失败或回调未到达 | 始终关联原任务进行状态恢复；查单失败和等待超时不触发新生成 |
| AC-14 | 成果下载／保存失败、磁盘空间不足，随后恢复；原链接失效 | 保存失败待恢复期间不结算；恢复下载与保存原结果而不再次生成；无法恢复时进入待核查，按已确认异常政策处理 |
| AC-15 | 多结果规格出现缺失、部分成功或部分保存失败 | 未确认规则时规格不可上架；确认后完整交付、部分交付与结算均严格按该政策，不能自行采用按张扣费 |
| AC-16 | 长期待核查或保存失败达到核查期限；人工处置后收到迟到成果 | 进入有责任人与证据的人工处理；无成功交付证据不得结算；期限本身不证明上游失败；已释放后不自动补扣，交付按已确认迟到政策 |
| AC-17 | 页面刷新、关闭、SSE 断线，再次打开原会话 | 连接状态不决定后台任务成败；读取已持久化任务、消息和成果，不重复受理；未保存流式片段是否可恢复依接口能力说明 |
| AC-18 | 文案复制、图片预览下载、视频播放下载；筛选作品 | 获取本人完整成果；作品类别、任务与会话关联可核对；重新生成保留原成果与费用记录 |
| AC-19 | 查询历史会话、任务、作品及积分流水 | 仅查询本人数据；显示服务端持久化状态、可用与冻结积分及每笔冻结去向；异常处置原因可查 |
| AC-20 | 伪造来源、跨任务、跨 Agent、重复、乱序及终态迟到回调 | 鉴权与防重放有效；核对已绑定任务，不采信任意用户归属；不串改任务、倒退阶段、逆转终态或重复结算；冲突记录可核查 |
| AC-21 | 用户猜测其他账户的会话、任务、素材、作品 ID 或文件链接 | 每个资源接口和下载／预览请求均校验所有权；越权访问失败，不泄露其他用户内容 |
| AC-22 | 不具备内容授权的管理员查询任务，再申请并获内容授权访问 | 常规任务诊断不暴露正文；只有单独授权可访问用户内容；记录对象、原因、操作人和时间；秘密不进入配置响应、快照或错误日志 |
| AC-23 | 伪造文件类型、用户文件名含路径、超限上传或结果下载 | 校验实际类型／大小；文件由服务端随机标识和隔离路径保存；拒绝越界、不支持和超限内容并给出明确原因 |
| AC-24 | 结果链接指向未批准来源、内网／回环／云元数据地址或重定向到此类地址 | 校验主机、解析地址及每次重定向；拒绝危险或未授权地址；体积、时限、重定向次数按已确认配置限制 |
| AC-25 | 并发生成预留空间，任务完成／失败／受理失败，异常任务长期未完成 | 不重复分配剩余容量；保存后核算实际占用并释放剩余预留；回收幂等；异常任务预留按已确认期限与策略处理 |
| AC-26 | 删除作品／素材后查看历史消息、使用旧链接、重新生成，并进行物理清理 | 按已确认删除、历史呈现、恢复与容量政策执行；保留账本和任务审计；在途素材不清理；有保留引用时不物理删除；素材缺失时要求重新上传 |
| AC-27 | 停用账号时存在有效登录会话和未结束任务 | 阻止登录、新受理与受保护访问；已有任务、冻结和作品记录不丢失；后续任务处理与恢复账户行为符合已确认政策 |
| AC-28 | 从工作台及个人中心打开充值入口 | 进入说明页、显示当前积分与后续支付提示；不创建支付订单、不调用支付渠道、不增加积分 |
| AC-29 | 发布官网案例，再按已确认流程撤回授权 | 仅公开有授权依据的真实案例；保留来源与归属；不暴露私有原文件；授权撤回后下架及公开副本处理符合已确认规则 |
| AC-30 | 电脑端及手机基本响应式检查；更新应用和执行备份恢复演练 | 主要流程可操作；素材／作品保存于持久目录，不被更新覆盖；数据库与文件可按已确认恢复方案核对；监控和容量告警可验证 |

验收通过的最小证据包含：执行配置、输入／操作、平台任务与上游任务标识（适用时）、前后余额及流水、状态迁移、交付文件或消息、实际结果、执行人和时间。截图不得代替账本、权限和恢复场景的服务端证据。

## 16. 建议开发顺序

1. 明确 Agent 接口能力和首批可用规格，建立包含超时、重复通知和结果保存失败场景的模拟服务。
2. 账户、权限和后台基础框架，完成积分账户、账本和注册赠送。
3. 将任务持久化、输入快照、报价确认、积分冻结／结算／释放和可恢复派发作为一条流程实现，配置后台规格与价格。
4. 统一创作窗口、服务器文件存储、任务查询与流式展示，先用模拟服务验证主流程和异常恢复。
5. 依次接入文案、图片、视频 Agent，按实际接口验证安全重试、回调和真实成果保存。
6. AI 提示词辅助、作品库、历史记录及删除规则，完善后台异常处置。
7. 宣传首页、充值说明页、响应式适配与基础运行检查。
8. 联调并完成首版验收。

各阶段可在不依赖真实 Agent 的部分使用模拟接口验证，正式上线前需完成真实服务联调。

## 18. 交付与上线检查

- 需求交付：本终稿、保留的初稿、独立评审记录、问题修复记录。文档评审通过不等于软件验收通过。
- 开发准备：指定 D-01～D-12 的确认负责人；可以先完成模拟接口和不依赖未决政策的账户、任务、账本及页面骨架。
- 联调准备：Agent 能力矩阵、字段协议、首批规格／报价、生产配额、异常与存储策略按适用启用门槛确认。
- 上线检查：三个真实 Agent 分别联调；执行全部适用 AC 场景并附证据；确认生产配置、数据保护、案例授权、监控和备份恢复。未满足的生产功能不启用；若影响首版必需主流程，则首版整体不通过上线检查。
- 后续支付：单独确认充值、退款和对账需求并验收，不纳入首版验收或收入统计。
